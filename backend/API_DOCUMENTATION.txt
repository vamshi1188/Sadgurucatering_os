SADGURU CATERING OS BACKEND API
================================

Base URL
--------
/api/v1

The API is served by the backend HTTP server. In local development the full
base URL is commonly:

http://localhost:8080/api/v1

All successful JSON responses use this envelope:

{
  "data": <response data>
}

Errors use this envelope:

{
  "error": {
    "code": "<error code>",
    "message": "<human-readable message>"
  }
}

Authentication
--------------

Login returns an opaque bearer token. Store it in secure client-side storage
and send it in the Authorization header. Tokens expire after 24 hours and are
stored only as hashes by the backend. The login endpoint does not set a cookie.

The initial owner account is created only when the users table is empty. Its
username and password come from `[auth.bootstrap_owner]` in the backend
configuration. The example config uses `admin` / `admin123` for development;
production configuration must use a password of at least 12 bytes. The account
is marked to require a password change at first login.

Protected API operations are available to active owners and supervisors. Reads
are available to both roles; event and finance writes and user administration
require the owner role. Authentication accepts bearer tokens only. Accounts
marked `must_change_password` must change
their password before using other protected API operations.


1. HEALTH
---------

GET /api/v1/health

Authentication: Not required.

Usage:

curl http://localhost:8080/api/v1/health

Success: 200 OK

{
  "data": {
    "status": "ok"
  }
}


2. AUTHENTICATION
-----------------

POST /api/v1/auth/login

Authentication: Not required.

Request body:

{
  "username": "admin",
  "password": "admin123"
}

Usage:

curl -i \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' \
  http://localhost:8080/api/v1/auth/login

Success: 200 OK
The response contains the bearer token and public user information. No
Set-Cookie header is returned.

{
  "data": {
    "token": "OPAQUE_TOKEN",
    "user": {
      "id": 1,
      "username": "admin",
      "role": "owner",
      "must_change_password": true
    }
  }
}

Possible errors:
- 400: invalid or unreadable request body
- 401: invalid username or password
- 429: too many login attempts
- 500: a session cannot be created


GET /api/v1/auth/session

Authentication: Required.

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  http://localhost:8080/api/v1/auth/session

Success: 200 OK

{
  "data": {
    "user": {
      "id": 1,
      "username": "admin",
      "role": "owner",
      "must_change_password": true
    }
  }
}

Possible errors:
- 401: authentication required or session is invalid


POST /api/v1/auth/change-password

Authentication: Required.

Request body:

{
  "current_password": "admin123",
  "new_password": "A-strong-new-password"
}

The new password must be 12-72 bytes. Other active sessions are revoked while
the current session remains valid.

POST /api/v1/auth/logout

Authentication: Not required. A supplied bearer token is revoked.

Usage:

curl -i -X POST -H "Authorization: Bearer OPAQUE_TOKEN" \
  http://localhost:8080/api/v1/auth/logout

Success: 200 OK, `{"data":{"authenticated":false}}`.


3. USER MANAGEMENT
------------------

All user management routes require an active owner session.

GET /api/v1/users

Lists users. User responses include id, username, role, is_active,
must_change_password, and created_at.

POST /api/v1/users

Creates an active user. Passwords must be 12-72 bytes. The new user is
required to change the password on first login.

{
  "username": "supervisor-one",
  "role": "supervisor",
  "password": "An-initial-password"
}

PATCH /api/v1/users/{id}

Updates one or more of `username`, `role` (`owner` or `supervisor`), and
`is_active`.
The last active owner cannot be demoted or deactivated.

DELETE /api/v1/users/{id}

Deletes a user and revokes their sessions. The last active owner cannot be
deleted.

POST /api/v1/users/{id}/reset-password

Request body: `{"password":"A-new-temporary-password"}`. This requires a
12-72 byte password, marks the user to change it at next login, revokes all of
that user's sessions, and returns 200 with `{"data":{"reset":true}}`.

Successful create returns 201, update returns 200 with the updated user, and
delete returns 204.
Administrative changes are written to the user audit log.


4. EVENTS
---------

Event statuses are:
- upcoming
- running
- completed

The normal lifecycle is:
upcoming -> running -> completed

POST /api/v1/events

Authentication: Required.

Creates an event. The status is normally initialized by the backend as
upcoming. The service only permits valid event status values.

Request body:

{
  "title": "Wedding Reception",
  "event_date": "2026-09-05",
  "venue": "Sadguru Function Hall",
  "guest_count": 500
}

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title":"Wedding Reception",
    "event_date":"2026-09-05",
    "venue":"Sadguru Function Hall",
    "guest_count":500
  }' \
  http://localhost:8080/api/v1/events

Success: 201 Created

{
  "data": {
    "id": 1,
    "title": "Wedding Reception",
    "event_date": "2026-09-05",
    "venue": "Sadguru Function Hall",
    "guest_count": 500,
    "status": "upcoming",
    "created_at": "2026-09-03T10:00:00Z",
    "updated_at": "2026-09-03T10:00:00Z"
  }
}

Possible errors:
- 400: invalid request body or event fields
- 401: authentication required


GET /api/v1/events

Authentication: Required.

Returns all events ordered by event date ascending and ID ascending.

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" http://localhost:8080/api/v1/events

Success: 200 OK

{
  "data": [
    {
      "id": 1,
      "title": "Wedding Reception",
      "event_date": "2026-09-05",
      "venue": "Sadguru Function Hall",
      "guest_count": 500,
      "status": "upcoming",
      "created_at": "2026-09-03T10:00:00Z",
      "updated_at": "2026-09-03T10:00:00Z"
    }
  ]
}

Possible errors:
- 401: authentication required
- 500: unable to list events


GET /api/v1/events/{id}

Authentication: Required.

Returns one event by its positive integer ID.

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" http://localhost:8080/api/v1/events/1

Success: 200 OK
The response data is one event object with the same fields as the event list.

Possible errors:
- 401: authentication required
- 404: event not found or invalid event ID
- 500: unable to retrieve event


DELETE /api/v1/events/{id}

Authentication: Required.

Deletes an event and its associated income and expense entries.

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  -X DELETE \
  http://localhost:8080/api/v1/events/1

Success: 204 No Content

Possible errors:
- 401: authentication required
- 404: event not found or invalid event ID
- 500: unable to delete event


PATCH /api/v1/events/{id}/status

Authentication: Required.

Changes an event status. The request body must contain the target status.

Request body:

{
  "status": "running"
}

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  -X PATCH \
  -H "Content-Type: application/json" \
  -d '{"status":"running"}' \
  http://localhost:8080/api/v1/events/1/status

Success: 200 OK
Returns the updated event object.

Allowed transitions:
- upcoming -> running
- running -> completed

Completed events are immutable in the basic MVP flow. Reverse transitions and
upcoming -> completed are rejected.

Possible errors:
- 400: invalid body, status, or status transition
- 401: authentication required
- 404: event not found or invalid event ID


5. EVENT FINANCE
----------------

Money amounts are stored and returned as decimal strings. Do not calculate
business totals with JavaScript floating-point values. The backend calculates
income, expenses, and profit from PostgreSQL NUMERIC values.

POST /api/v1/events/{id}/income

Authentication: Required.

Adds one income entry to an event. Multiple entries are supported.

Request body:

{
  "description": "Catering advance",
  "amount": "50000.00"
}

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"description":"Catering advance","amount":"50000.00"}' \
  http://localhost:8080/api/v1/events/1/income

Success: 201 Created

{
  "data": {
    "id": 10,
    "event_id": 1,
    "description": "Catering advance",
    "amount": "50000.00",
    "created_at": "2026-09-03 10:15:00+00"
  }
}

Validation:
- description is required and may be at most 255 characters
- amount must be greater than zero
- amount may contain at most two decimal places

Possible errors:
- 400: invalid description or amount
- 401: authentication required
- 404: event not found


DELETE /api/v1/events/{event_id}/income/{income_id}

Authentication: Required.

Deletes one income entry belonging to the specified event.

Success: 204 No Content

Possible errors:
- 401: authentication required
- 404: income not found or not associated with the event
- 500: unable to delete income


POST /api/v1/events/{id}/expenses

Authentication: Required.

Adds one expense entry to an event. Multiple entries are supported.

Request body:

{
  "description": "Food supplies",
  "amount": "20000.00"
}

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"description":"Food supplies","amount":"20000.00"}' \
  http://localhost:8080/api/v1/events/1/expenses

Success: 201 Created
Returns an entry object with id, event_id, description, amount, and created_at.

Possible errors:
- 400: invalid description or amount
- 401: authentication required
- 404: event not found


DELETE /api/v1/events/{event_id}/expenses/{expense_id}

Authentication: Required.

Deletes one expense entry belonging to the specified event.

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  -X DELETE \
  http://localhost:8080/api/v1/events/1/expenses/10

Success: 204 No Content

Possible errors:
- 401: authentication required
- 404: expense not found or not associated with the event
- 500: unable to delete expense


GET /api/v1/events/{id}/financials

Returns the event's aggregated financials and all income and expense entries.

Usage:

6. DASHBOARD REPORTING
----------------------

GET /api/v1/dashboard/summary

Authentication: Required.

Returns reporting totals calculated directly from PostgreSQL, plus the
individual events in the requested inclusive date range. Events are not merged;
each event keeps its own financial totals for drill-down.

Query parameters:
- from: inclusive date in YYYY-MM-DD format
- to: inclusive date in YYYY-MM-DD format

If both parameters are omitted, the current date is used. If only from is
provided, to defaults to the same date.

Usage for today:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  "http://localhost:8080/api/v1/dashboard/summary?from=2026-09-03&to=2026-09-03"

Usage for a date range:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  "http://localhost:8080/api/v1/dashboard/summary?from=2026-09-01&to=2026-09-30"

Success: 200 OK

    "from": "2026-09-01",
    "to": "2026-09-30",
    "event_count": 2,
    "upcoming_count": 1,
    "running_count": 1,
    "completed_count": 0,
    "total_income": "70000.00",
    "total_expenses": "25000.00",
    "profit": "45000.00",
    "events": [
      {
        "id": 1,
        "title": "Event A",
        "event_date": "2026-09-05",
        "venue": "Hall A",
        "guest_count": 500,
        "status": "upcoming",
        "total_income": "50000.00",
        "total_expenses": "18000.00",
        "profit": "32000.00"
      },
      {
        "id": 2,
        "title": "Event B",
        "event_date": "2026-09-06",

GET /api/v1/finance/summary

Authentication: Required.

Returns business-wide income, expenses, profit, event breakdown, and a
paginated list of income and expense transactions. Date filters apply to
transaction created_at timestamps using UTC calendar-day boundaries. The
start date is inclusive and the end date is exclusive internally (the
requested to date is included in full).

Query parameters:
- period: today, this_month (default), last_30_days, custom, or all_time
- from: required with period=custom; inclusive YYYY-MM-DD
- to: required with period=custom; inclusive YYYY-MM-DD
- page: one-based transaction page, default 1, range 1 through 1,000,000
- page_size: transaction count per page, default 20, range 1 through 100

For today, this_month, and last_30_days, the API calculates the period from
the current UTC date. last_30_days includes today and the previous 29 days.
For all_time, from and to are omitted from the response. Custom date filters
must be supplied together, use valid dates, and from must not be after to.
from and to are only accepted with period=custom.

Transactions are ordered by created_at descending, then transaction type,
event ID, and transaction ID for stable pagination. Transactions include
their event ID and title. Events in the breakdown are those with at least one
income or expense transaction during the selected period. All monetary values
are PostgreSQL numeric strings; profit is calculated in PostgreSQL.

Usage:

curl -i -H "Authorization: Bearer OPAQUE_TOKEN" \
  "http://localhost:8080/api/v1/finance/summary?period=this_month&page=1&page_size=20"

Success: 200 OK

{
  "data": {
    "period": "this_month",
    "from": "2026-09-01",
    "to": "2026-09-30",
    "total_income": "70000.00",
    "total_expenses": "25000.00",
    "profit": "45000.00",
    "events": [
      {
        "event_id": 1,
        "title": "Wedding Reception",
        "event_date": "2026-09-05",
        "status": "completed",
        "total_income": "50000.00",
        "total_expenses": "18000.00",
        "profit": "32000.00"
      }
    ],
    "transactions": [
      {
        "type": "income",
        "id": 10,
        "event_id": 1,
        "event_title": "Wedding Reception",
        "description": "Catering advance",
        "amount": "50000.00",
        "created_at": "2026-09-03 10:15:00+00"
      }
    ],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 1,
      "total_pages": 1
    }
  },
  "meta": {}
}

Possible errors:
- 400: invalid period, date range, or pagination parameters
- 401: authentication required
- 500: unable to retrieve finance report


Common HTTP status codes
------------------------

200 OK       Request completed successfully.
201 Created  Resource or finance entry created.
400 Bad Request
             Request body or query parameters are invalid.
401 Unauthorized
             Authentication is missing or invalid.
404 Not Found
             Resource or event does not exist.
500 Internal Server Error
             The backend could not complete the operation.
