# v1.0.4.3 — Environment Configuration

## Objective

Centralize frontend environment configuration so environment variables are
read from one controlled location.

## Scope

- Add frontend API base URL environment configuration
- Centralize `import.meta.env` access
- Validate required configuration
- Add unit tests for configuration success and failure paths

## Implementation

- Added `frontend/.env.example`
- Added `frontend/src/lib/config.ts`
- Added `frontend/src/lib/config.test.ts`
- Existing root `.gitignore` confirmed to cover frontend `.env` files while
  allowing `.env.example`
- `import.meta.env` is accessed only by `src/lib/config.ts`

## Configuration

Required variable:

`VITE_API_BASE_URL=http://localhost:8080/api/v1`

The configuration module throws a clear error when the required variable
is missing and exposes a frozen typed configuration object.

## Validation

- Configuration success test — PASS
- Missing configuration failure test — PASS
- `npx tsc --noEmit` — PASS
- `npm run build` — PASS
- `git diff --check` — PASS
- `import.meta.env` access centralized in `src/lib/config.ts`

## Acceptance Criteria

- [x] `.env.example` documents the required variable
- [x] Missing `VITE_API_BASE_URL` produces a clear error
- [x] Success path is unit tested
- [x] Missing-variable failure path is unit tested
- [x] Environment access is centralized

## Known Limitations

Configuration currently contains only the API base URL. Additional environment
configuration will be introduced only when required by later frontend
capabilities.
